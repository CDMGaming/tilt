Measures how long a key press takes to become sound, through the same path the app's synths will use (Web MIDI → AudioWorklet → output).

2 · Inputs

MIDI not enabled.

Play any key or pad on your MIDI controller. Without one, press A–K on the computer keyboard, or run the automatic test.

3 · Software path: key event → sound leaving the audio device

last note
—

Calculated per note from the frame the synth started on, mapped to wall-clock time with the browser's output timestamp. It includes the output buffer and the latency the Windows driver reports. It cannot see USB MIDI transport (usually 1–3 ms) or delay the driver doesn't report, so it can read low. The microphone test below measures the whole path.

4 · Acoustic test (optional, measures the whole path)

Put the mic near the controller and turn the speakers up. Each note then plays a short high beep. The test times the gap between the sound of your finger hitting the pad and the beep coming out of the speakers. Pads work better than keys, because a key sends its note before it hits bottom. Speakers only, not headphones.
